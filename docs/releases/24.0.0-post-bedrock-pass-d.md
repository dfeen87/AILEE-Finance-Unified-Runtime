## Verified defects and before-fix evidence

**High severity: destination and live authorization were independent of mode.**
The daemon loads the environment destination and overwrites only `is_live` with
the CLI mode. The adapter never reads `is_live`, enabling paper/live mismatches
whenever credentials are present. `loadConfigFromEnv()` grants live mode when
the URL lacks the substring `paper`; a URL containing that substring is instead
labeled paper. Neither rule validates the actual host or grants operator consent.
The registry inherits this unsafe inference outside the CLI confirmation guard.

**Related destination-policy defect:** permissive host/port parsing strips path
suffixes and uses `atoi` on malformed ports. Unknown hosts, unsupported schemes,
userinfo, and ambiguous origins can be enabled; non-HTTPS schemes are rebuilt as
HTTP. This establishes unsafe configuration acceptance, not a claim that every
malformed string successfully connects. No production URL was executed.

Tests were written and run before implementation changes:

```sh

  tests/test_alpaca_authorization.py tests/test_alpaca_transport.py
```

The initial 102-case matrix produced **55 failed, 47 passed** in 26.27 seconds;
all 33 existing Pass C transport checks passed. Failures independently establish
enabled paper/live mismatches, unauthorized live configuration, unsafe registry
inference, malformed-destination acceptance, and local authenticated operations
that should have been rejected. Separate local probes observed:

```json

{"case":"ignored destination suffix","result":"local-order","requests":[["POST","/v2/orders",true]]}
```

The boolean records receipt of the synthetic key. No real credentials or broker
requests were used. After expanding the matrix, its final version was replayed
against an archive of the untouched baseline: **58 failed, 89 passed** in 55.80
seconds. This includes an actual CLI dry-run that silently accepts an invalid
environment destination and observes account equity before correction.

The driver inspects official/unknown remote URLs only through construction and

## Minimal correction and compatibility boundary

`AlpacaExecution` validates one origin during non-mock construction and stores
that normalized origin for all four client paths. A rejected configuration
leaves the adapter disabled before any client, DNS lookup, or socket operation.
Existing empty/false/negative error returns remain unchanged. The daemon exits
nonzero when broker configuration is disabled.

| Destination/state | Required configuration and behavior |
| --- | --- |
| `https://paper-api.alpaca.markets` | Paper mode. Implicit or explicit port 443; optional trailing slash. |
| `https://api.alpaca.markets` | Live mode **and** `live_authorized=true`; same HTTPS/443 restrictions. |
| Exact `localhost`, `127.0.0.1`, or `[::1]` origin | Explicit local simulation exception. HTTP/HTTPS and valid ports 1–65535; live mode still requires consent. HTTPS still verifies certificates and hostnames. |
| Unknown/custom remote host | Disabled. No inference from hostname substrings. |
| Malformed origin, userinfo, non-root path, query, fragment, escape, invalid scheme/port | Disabled. No repair or fallback to another destination. |
| Mock mode | No network client regardless of URL, mode, consent, or credentials; existing mock behavior preserved. |

Scheme and host case are normalized. No production HTTP or nonstandard broker
port is accepted. A local simulation can exercise either nominal trading mode;
this exception is an allowlist of explicit local origins, not authorization for
an arbitrary custom production broker. Only empty/root paths are accepted because
operations already use fixed `/v2/...` routes; silently discarding a supplied path
is no longer allowed.

`loadConfigFromEnv()` now leaves mode paper and consent false. Environment data
cannot authorize live operation, including through the stock registry factory.
The daemon explicitly passes the CLI mode and confirmation state to the adapter;
an environment URL contradicting the CLI mode is rejected rather than rewritten.
Live CLI use requires both confirmation and a compatible explicit destination;
confirmation with the default paper destination fails closed in non-mock mode.

The smallest new public semantic is **`AlpacaConfig::live_authorized`**, a
default-false consent bit; `DaemonConfig` carries the same bit. `is_live` remains
the requested mode. Existing public function signatures, provider interfaces,
order schemas, and paper/mock defaults remain intact. Programmatic live callers
must now deliberately set both bits and a compatible origin. The configuration
and adapter class layouts therefore change; precompiled consumers must rebuild.
An operator identity/token system or a registry-wide live authorization API would
require broader architecture and is not introduced here. The stock environment
factory intentionally cannot grant live execution.

The scheme-aware HTTPS transport from PR #106 remains in place. No verification
option is disabled. Existing httplib redirect behavior remains disabled, with new
302/307 controls proving that HTTPS responses cannot redirect credentials to a
different local HTTP destination. No quantity, sizing, signal, financial formula,
governance threshold, runtime pipeline, or order-body change is made.

Dry-run still permits compatible account observations and produces no mutating
broker requests. Missing consent or invalid configuration prevents even those
observations. Cancellation/flattening after lockout remain risk-reducing actions;
lockout is not redefined as revocation of a valid destination configuration.

## Blocked attempts and remaining unvalidated risks

The initial `git fetch` could not reach the proxy from the socket-restricted
sandbox. Repeating with network access succeeded and established the exact
baseline independently of GitHub connector evidence. The initial C++ suite ran
197 checks but failed two FS-Gateway listener checks with `Operation not permitted`;
the loopback-enabled rerun passed all 197. These infrastructure attempts are not
endpoint-authorization defects. No required local check remains blocked.

Production Alpaca authentication, orders, and endpoint operation were deliberately
not exercised. Official origins were checked only through local configuration
validation. IPv4/IPv6 literal acceptance is tested, but no IPv6 network round trip
is claimed; real integration tests bind IPv4 loopback. Arbitrary remote custom
brokers, DNS/OS compromise, or a trusted local service forwarding upstream are
outside this origin policy. No new full Docker image, cross-platform/toolchain,
financial-performance, or full-runtime sanitizer result is inferred. Earlier
Docker image validation remains blocked in prior evidence and was not retried.

Consent is a caller-supplied bit, not authenticated operator identity or proof of
broker account type. This pass prevents missing/contradictory configuration from
silently authorizing a destination; it does not introduce a central authorization
service. The Python runner remains a simulation. Pass C's acknowledgment, replay,
ledger, durable recovery, numerical execution-ingress, and settlement concerns
remain unresolved and unmodified; no assurance about those architectures follows
from this endpoint correction.

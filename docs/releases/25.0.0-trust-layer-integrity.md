# AILEE Finance Unified Runtime v25.0.0 — Trust Layer Integrity

**Status:** Unreleased source candidate in PR #108. The version bump is not a tag, published package, deployable artifact or production approval.

## Why a major version

This update intentionally changes runtime contracts. Previously tolerated malformed numerical evidence, unsafe SELL fallback ceilings, unsupported non-mock broker requests and lossy audit recovery are now rejected or fail closed. Existing integrations may require adaptation; v24.0.0 is retained as the historical BEDROCK baseline.

## Included architectural changes

- Finite and typed evidence validation in Python and native finance governance; bounded SELL and fallback quantities, preserving hard position caps
- Configuration, history and replay-state safeguards, including chronological cursor preservation
- Durable, private non-mock order-intent journaling; bounded BUY LIMIT requests, explicit client identity and reserved unknown outcomes
- Recoverable and chained native audit evidence, with corruption and ambiguous input rejected
- Canonical sampled `ailee-delta-v/v1` evidence in Python and C++, using the documented composite-trapezoidal integration; mathematical evidence does **not** authorize orders
- CI, dependency, transport and loopback security hardening

## Migration checks

1. Read [execution integrity and broker migration](execution-integrity-hardening.md) before enabling any non-mock adapter.
2. Supply valid, bounded, finite market inputs and explicit non-mock BUY LIMIT intent; do not assume former permissive defaults remain supported.
3. Configure and protect a durable, private intent journal and test restart/unknown-outcome handling before executing against any broker.
4. Treat accepted orders as pending until independently reconciled; broker acceptance is not a verified fill.
5. Migrate legacy audit records without silently resetting a corrupt or incomplete chain. Validate restart and recovery semantics.
6. Verify that mathematical evidence is recorded and validated without changing SELL authorization.
7. Rerun Python and native regression suites, SDK relocation, REST lifecycle and end-to-end simulations in the intended environment.
